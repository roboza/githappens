# 00 — Project Overview & Architecture

> Name: **GitHappens**. A cross-platform desktop Git GUI built around a fast, interactive commit graph.

## 1. Goal

Build the core of GitHappens: a fast, visual, cross-platform Git client centered on an interactive commit graph, with drag-and-drop Git operations, a built-in diff/merge tool, hosting-provider integrations (GitHub, GitLab, Bitbucket, Azure DevOps), and productivity features (workspaces, launchpad, AI commit messages, terminal).

Cloud services (account sync, Cloud Patches, Team view, Insights) are spec'd as **optional later phases** built on our own backend or omitted.

## 2. Technology decisions (binding for all specs)

| Concern | Decision | Rationale |
|---|---|---|
| Shell | **Electron** (latest stable) | Proven for desktop Git clients; mature, cross-platform, Node access for git. |
| UI | **React 19 + TypeScript 6.0 (strict)** | Component model fits panel-heavy UI. TS pinned `~6.0` until typescript-eslint supports TS 7. |
| State | **Zustand** stores per domain + **TanStack Query** for async git/provider data | Simple, fast, cache invalidation built in. |
| Styling | CSS variables theme tokens + CSS Modules | Enables light/dark/custom themes (spec 13). |
| Git engine | **Git CLI** (bundled via `dugite`-style portable git) wrapped by a typed `GitService` in the main process. Optional `nodegit`/libgit2 never required. | CLI is complete (LFS, hooks, credential helpers, worktrees, signing) and matches user's git behavior. |
| Commit graph render | **HTML Canvas 2D** (virtualized rows) for lanes/edges; DOM for row text columns | Must handle 100k+ commits at 60fps. |
| Code editor / diff | **Monaco Editor** | Syntax highlighting, inline/split diff, file editing. |
| Terminal | **xterm.js + node-pty** | Integrated terminal (spec 12). |
| IPC | Typed request/response + event channels via `contextBridge` (no `nodeIntegration` in renderer) | Security. |
| File watching | `chokidar` (or `@parcel/watcher`) on worktree + `.git` | Auto-refresh. |
| Secrets | OS keychain via `keytar` / Electron `safeStorage` | Provider tokens, never plaintext. |
| Persistence | JSON files in `app.getPath('userData')` (settings, profiles, tabs, workspaces) | Simple, portable. |
| Packaging | `electron-builder` (dmg, nsis/msi, AppImage/deb/rpm/snap) + auto-update | Native installers and updates on every desktop platform. |
| Build | `electron-vite` 5 + Vite 7 (pinned: electron-vite 5 supports Vite ≤ 7) | One config for main / preload / renderer. |
| Tests | Vitest (unit), Playwright for Electron (e2e), fixture repos generated by scripts | |

## 3. Process architecture

```
┌────────────────────────── Main process (Node) ──────────────────────────┐
│ AppLifecycle · WindowManager · MenuBuilder · AutoUpdater                 │
│ RepoManager ── per-open-repo: GitService, RepoWatcher, OperationQueue   │
│ ProviderService (GitHub/GitLab/Bitbucket/Azure) · AuthService (OAuth)   │
│ SettingsStore · ProfileStore · WorkspaceStore · SecretStore             │
│ PtyService (terminals) · AIService (commit msg / explain)               │
└──────────────▲───────────────────────────────────────────────▲──────────┘
               │ typed IPC (invoke / events)                    │
┌──────────────┴──────── Preload (contextBridge `window.api`) ──┴──────────┐
└──────────────▲───────────────────────────────────────────────────────────┘
┌──────────────┴──────────── Renderer (React) ─────────────────────────────┐
│ AppShell: TabBar · Toolbar · LeftPanel · Graph · RightPanel · StatusBar   │
│ Views: Graph, CommitDetail, WIP/Staging, Diff, MergeTool, PR, Launchpad,  │
│        Workspaces, Preferences, Terminal, CommandPalette, Onboarding      │
└──────────────────────────────────────────────────────────────────────────┘
```

Rules:
- **Every git command runs in the main process** through `GitService`; the renderer never spawns processes.
- **One `OperationQueue` per repo** serializes mutating git ops (avoids `index.lock` races); read-only ops may run concurrently.
- Long ops (clone, fetch, push, rebase) emit progress events and are cancelable.
- Every mutating op records an entry in the **Undo journal** (spec 05) before executing.

## 4. Repository layout of the code we will build

```
/apps/desktop
  /src/main         # Electron main: services, ipc handlers
  /src/preload      # contextBridge API
  /src/renderer     # React app
  /src/shared       # types, IPC contract, constants
/packages/git       # GitService: command builders + output parsers (pure, unit-testable)
/packages/graph     # lane-assignment algorithm + canvas renderer
/packages/providers # GitHub/GitLab/Bitbucket/Azure clients
/services/oauth-broker  # tiny token-exchange service: GitHub/Bitbucket/Atlassian OAuth need a
                        # client secret a desktop app can't hide (GitHub device flow = fallback). Spec 10.
/services/cloud         # OPTIONAL Fastify/Postgres/S3 backend for sync, cloud patches, team view. Spec 14.
/test/fixtures      # scripts that generate repos (merges, conflicts, submodules, LFS)
/specs              # this folder
```

**Git version policy:** bundled git ≥ **2.38** (we control it; enables `merge-tree --write-tree` for conflict prediction). Supported system git ≥ **2.36** (`worktree list -z`); features needing 2.38 are feature-detected and hidden on older git.

**Reserved ref namespace:** `refs/githappens/*` holds undo-journal targets (spec 05) and is hidden from the graph and left panel (specs 02, 04).

## 6. Spec template (every feature spec follows this)

1. **Purpose** — what the feature does and why users care.
2. **Reference behavior** — researched description of how the feature behaves.
3. **User stories** — `As a … I want … so that …`.
4. **UI specification** — layout, components, states (empty/loading/error), interactions, shortcuts.
5. **Data model & IPC** — TypeScript interfaces, IPC channels.
6. **Git implementation** — exact git commands / parsing.
7. **Step-by-step implementation plan** — numbered, ordered, each step independently testable.
8. **Edge cases** — detached HEAD, empty repo, huge repos, bare repos, unicode paths, CRLF, etc.
9. **Acceptance criteria** — checklist.
10. **Out of scope / later**.

## 7. Glossary

- **WIP node** — the synthetic top-of-graph row representing uncommitted changes.
- **Ref** — branch (local/remote), tag, stash, HEAD.
- **Lane** — a vertical column in the graph a branch line occupies.
- **Op** — a mutating git operation routed through the `OperationQueue`.
- **Provider** — a Git hosting service (GitHub, GitLab, Bitbucket, Azure DevOps).
